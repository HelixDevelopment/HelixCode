# HXC-222 — untrack vendored node_modules in submodules/helix_agent

Submodule: `submodules/helix_agent` (repo `HelixDevelopment/HelixAgent`)
Commit: `0a48f8c29785099b0450fb04051b0219d4535ce2` (local only, NOT pushed)
Parent HEAD before this work: `9a50509d846d6a2224b612f013ff349fe597fe2a`

## What was wrong

`sdk/web/node_modules` (7,870 files) and `plugins/mcp-server/node_modules`
(1,037 files) — 8,907 files, ~104 MB — were tracked in git despite matching
the repo's own `.gitignore` (`node_modules/` at line 129, and the more
specific `plugins/mcp-server/node_modules/` at line 57). The patterns were
inert because git never applies ignore rules to paths already in the index;
`git rm -r --cached` was required first.

## Evidence index

- `01_sdk_web_npm_ci.log` / `02_mcp_server_npm_ci.log` — `npm ci` run from a
  clean scratch copy of each directory's committed `package.json` +
  `package-lock.json` only, BEFORE any untracking. Both exit 0, no network/
  auth issues (public npm packages only, no `.npmrc` anywhere in the repo).
- `09_..._path_diff.txt` / `10_..._path_diff.txt` — diff between the
  git-tracked path list and the `npm ci`-reproduced path list. The only
  differences are `.bin/*` symlinks (excluded from `find -type f`, expected)
  and `<pkg>/bin/*` real target files that were **never tracked at all** in
  either directory.
- `03_sdk_web_build_ORIGINAL_broken_tsc_before_regen.log` — `npm run build`
  against the **original, still-tracked-at-that-point** on-disk
  `node_modules`: fails with `tsc: command not found`. Root cause:
  `node_modules/.bin/tsc` is a symlink to `../typescript/bin/tsc`, but
  `typescript/bin/*` was never tracked (only `lib/` was), so the checked-out
  tree had a dangling symlink. The committed tree was already broken.
- `04_sdk_web_build_after_regen...log` / `05_..._jest_listTests...log` —
  after replacing the on-disk tree with the verified `npm ci` output: `tsc`

  test files. The `npm run build` script itself fails on a separate,
  pre-existing, unrelated gap (`tsconfig.cjs.json` / `.esm.json` /
  `.types.json` referenced by the script never existed in git history at
  all — out of scope for this fix).
- `06_mcp_server_build_after_regen.log` — `npm run build` (`tsc`) exits 0,

- `07_..._test_cors...log` / `08_..._test_host...log` — the package's own
  RED/GREEN guard tests (`test/cors_guard.test.js`,

## Scope discipline

`git status --porcelain` immediately before `git rm --cached` was 0 lines
(no concurrent agent activity in this checkout at that moment). Immediately
after `git rm --cached`, `git status --porcelain` showed exactly 8,907 `D`
lines, all under the two target trees (verified with a grep excluding both
pathspecs → 0 hits) — checked again immediately before the commit. The
commit's `git show --name-only` also confirms 0 files touched outside the
two trees.

## Not done here (explicitly out of scope / left as-is)

- Parent repo (`helix_code`) submodule pointer was **not** staged or
  committed — `git status` in the parent shows `submodules/helix_agent` as
  modified in the working tree only.
- Nothing was pushed to any submodule upstream.
- The two pre-existing, unrelated defects surfaced above (dangling `tsc`
  symlink in the previously-tracked tree; missing
  `tsconfig.{cjs,esm,types}.json` referenced by `sdk/web`'s `build` script)
  were not fixed — they are outside HXC-222's scope (untracking
  `node_modules`), and the first one is now moot since the regenerated tree
  no longer has the dangling symlink.
